# NES Smart Files AI — Android v0.1 Alpha

**تطبيق أندرويد أولي فعلي، وليس نموذج HTML.** يبدأ بفهرسة التخزين المشترك بعد الموافقة على صلاحية الملفات، ثم يتيح محادثة عربية تسترجع مقتطفات من الملفات. ويمكن استيراد نموذج GGUF من جهازك، أو من ZIP صادر عن المطور، أو تنزيل Qwen3.5-0.8B من Hugging Face مرة واحدة.

> **حالة التنفيذ:** مصدر برمجي كامل + مسار GitHub Actions لإنتاج **debug APK**. لم يتم اختبار APK أو تشغيله على جهاز فعلي في بيئة إعداد هذه الحزمة، ولا أزعم نجاح بناء Github Actions قبل تنفيذه. تستلزم بيئة البناء تنزيل الاعتمادات ومصدر llama.cpp، ولا يتضمن ZIP ملف APK أو نموذج GGUF.

## 1. ما الذي يعمل في هذا الإصدار؟

- تطبيق Android أصلي (Kotlin) بواجهة محادثة عربية ووضع فاتح.
- طلب صلاحية **All files access** من شاشة نظام أندرويد، ثم بدء الفهرسة الأولية تلقائيًا عند العودة للتطبيق.
- اكتشاف الملفات من التخزين المشترك الداخلي ومواقع SD الخارجية المتاحة. لا يمكنه فتح مجلدات التطبيقات الأخرى المحمية.
- حفظ أسماء الملفات والمسارات والأحجام وتواريخ التعديل وحالة الفهرسة في SQLite محلية.
- استخراج النصوص من TXT وMarkdown وHTML وJSON وXML وأكواد PHP/JS/TS/Python/Java/Kotlin/C/CSS/SQL وغيرها.
- استخراج نص PDF النصي باستخدام PDFBox-Android، حتى أول 75 صفحة/240 ألف حرف احترازيًا لكل ملف.
- استخراج أولي نصوص ومحتويات ZIP وDOCX وXLSX وPPTX وODT وEPUB (استخراج **جزئي**، وليس عرضًا دقيقًا لكل جدول).
- فهرسة بيانات الصور (الاسم والأبعاد)، والصوت/الفيديو (الاسم والمدة) **دون OCR أو تحويل الكلام إلى نص في هذه النسخة**.
- بحث في النص عبر SQLite FTS4 مع مرشحات المسارات/الأسماء، وروابط لفتح الملفات الأصلية من واجهة النتائج.
- محادثة مع نموذج GGUF محلي من خلال وحدة **AiChat** الرسمية التابعة للمثال Android في llama.cpp. لا توجد خدمة سحابية لاستنتاج النص.
- حفظ المحادثات والرسائل واستعادتها؛ زر محادثة جديدة وسجل المحادثات.
- اختيار نموذج من ملف `.gguf` أو ملف ZIP يضم `.gguf` أو مجلد فيه النموذج؛ أو تنزيل مباشر للنموذج المرجعي (حوالي 563 MB).
- التحقق من SHA-256 للنموذج الرسمي الذي نزل من الإنترنت، والتحقق من البصمة داخل ZIP إذا توفر `manifest.json` قبل ملف GGUF.
- فهرسة دورية عند الطلب عبر WorkManager مع تخطي استخراج المحتوى من الملفات التي لم تتغير؛ عند إعادة تشغيل التطبيق أو توقف الوظيفة يمكن معاودة الجولة.

## 2. مهم: ما الذي **لم يُنفّذ بعد**؟

- التمثيلات الدلالية Embeddings وANN وإعادة ترتيب النتائج: **لم تدمج بعد**؛ البحث الآن **نصي/اسمي**، وإن كان النموذج اللغوي قادرًا على صياغة إجابة باستخدام مقتطفاته.
- OCR العربي من الصور وملفات PDF المصورة: غير موجود في v0.1؛ البيانات الوصفية فقط للصور، وصفحات PDF الممسوحة قد تظهر `needs_ocr`.
- تفريغ التسجيلات الصوتية باستخدام Whisper، وفهرسة فيديوهات على مستوى المقاطع والتوقيتات: لم ينفذ بعد.
- العمليات الإدارية المتقدمة (إنشاء/نقل/حذف المجلدات، الفرز المتقدم، النسخ، فرز المكررات): لم تنفذ؛ واجهة v0.1 **محادثة وفهرسة فقط** وفق الأولوية الحالية.
- تصنيف متعدد الوكلاء / ذاكرة دلالية دائمة: لا تزال على خارطة الطريق. الموجود هو رسائل محفوظة وسياق محادثة ضمن محرك الاستدلال المحلي.
- لا يجري نسخ كل ملفات الهاتف إلى قاعدة البيانات: يخزّن **المقاطع المستخرجة المحدودة** وبيانات المصادر. الملفات الأصلية تبقى في أماكنها.

## 3. المتطلبات

- Android 13+ (minSdk 33)، ARM64؛ لأن وحدة `llama.cpp` المختارة تحدد Android 13 كحد أدنى.
- يفضل 6GB RAM أو أكثر، لكن التجربة على 4GB ممكنة بنموذج مكمّم صغير؛ السرعة والتوافق غير مضمونين دون اختبار.
- على GitHub Actions: JDK 21 للبناء، Android SDK 36 وNDK 29 وCMake 3.31.6 وGradle 8.13.
- **لا نحتاج Node.js ولا Capacitor** في هذا الإصدار الأصلي؛ بذلك لا تتكرر مشكلات Node/Capacitor الخاصة بمشروعك السابق.

## 4. كيف تنتج APK من GitHub؟

1. أنشئ مستودع GitHub جديدًا وارفع **محتويات** مجلد المشروع الموجود داخل ZIP إلى جذر المستودع.
2. افتح **Actions → Android APK - NES Smart Files → Run workflow**.
3. سيجلب الإجراء مصدر llama.cpp وموارد Android، ثم يبني `app:assembleDebug`.
4. افتح نتيجة البناء، وحمّل Artifact باسم `NES-Smart-Files-Android-APK`، ثم ثبّت APK على هاتف ARM64.
5. عند فتح التطبيق: امنحه صلاحية إدارة الملفات من الإعدادات. تبدأ الفهرسة تلقائيًا بعد العودة. ويمكن إعادة الفهرسة يدويًا.
6. اضغط «النموذج» واختر: التنزيل الرسمي / GGUF أو ZIP / مجلد النماذج.

**تنبيه:** إصدار Debug مناسب للاختبار الشخصي، وليس APK موقّعًا بتوقيع إصدار للنشر. عند إعادة تثبيته بتوقيع مختلف قد تفقد بياناته الخاصة.

### تثبيت المصدر المرافق للذكاء الاصطناعي محليًا على جهاز تطوير

```bash
bash scripts/fetch-llama.sh
# يحتاج إلى Android SDK/NDK/Gradle والإنترنت خلال البناء:
gradle :app:assembleDebug
```

مصدر AiChat الرسمي: https://github.com/ggml-org/llama.cpp/tree/master/examples/llama.android

**قفل المصدر:** السكربت يستخدم `master` افتراضيًا كنقطة بناء أولية؛ يجب تثبيت `LLAMA_REF` على commit SHA بعد أول بناء أخضر ناجح. وهذا يستلزم أن يكون SHA متاحًا لعملية checkout. يحتفظ الإجراء بعنوان الالتزام المجلوب ضمن `vendor/llama-ref.txt` ويحمّله كـArtifact. هذا قيد معروف لإعادة الإنتاج في النسخة الأولية.

## 5. حزمة نماذج من المطور

النماذج غير موجودة في ZIP هذا. لتجهيز حزمة أوفلاين للمستخدم، نزّل GGUF على الكمبيوتر ثم نفّذ:

```bash
bash scripts/package-model.sh /path/to/Qwen3.5-0.8B-Q4_0.gguf
```

سينشئ ملف ZIP فيه `manifest.json` يحتوي SHA-256 متبوعًا بملف GGUF. يمكن نقل الملف بالبلوتوث أو USB أو بطاقة ذاكرة ثم فتحه من شاشة «النموذج». تحقق SHA-256 يحمي من فساد محتوى ZIP لكنه **لا يثبت هوية المطور دون توقيع رقمي موثوق**.

**النموذج المرجعي لتنزيل التطبيق:**

- URL: `https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF/resolve/9447f74101aeb4e93621884dfa36ee8effb8831b/Qwen3.5-0.8B-Q4_0.gguf`
- SHA-256: `57d1997790d1744fba5b40a7317df71ea5e2acee28c47e78f0cce39c0703f8cf`
- الترخيص المعلن للنموذج Apache-2.0. راجع التراخيص قبل إعادة التوزيع.

## 6. قيود وأمان

- `MANAGE_EXTERNAL_STORAGE` يتطلب إذنًا خاصًا ويخضع لسياسة صارمة في Google Play؛ النشر في المتجر يتطلب مراجعة إضافية. استخدامه هنا بسبب أن وظيفة التطبيق الرئيسية بحث جميع ملفات التخزين المشترك.
- لا يمكن الوصول إلى `Android/data` التابعة للتطبيقات الأخرى أو قواعد بياناتها الخاصة دون صلاحيات استثنائية.
- **لا تعطي الإجابات انطباعًا أن جميع الصور والصوت قد تم تحليلها**؛ يرى المستخدم في الفهرس عدد الملفات ذات بيانات وصفية فقط.
- يفهرس التطبيق مقتطفات الملفات في قاعدة داخلية؛ لا يرسلها لأي خدمة خارجية. طلب الإنترنت الوحيد في الكود الحالي هو تنزيل النموذج بناءً على اختيار المستخدم.
- قد ينقطع المسح الطويل بسبب سياسات البطارية؛ WorkManager يعيد الجدولة وينبغي ألا يعتبر غياب النتيجة دليلًا على عدم وجودها.
- الملفات الضخمة والمستندات المكتبية والأرشيفات يُفهرس منها محتوى جزئي فقط ضمن حدود السلامة.
